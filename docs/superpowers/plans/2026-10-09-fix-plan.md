## Task 2: Koniec z fałszywymi „obrazkami" (M) — R5

Problem: URL bez rozszerzenia = „obrazek"; HEAD czyta tylko `content-length`, ignoruje `content-type`.

**Files:**
- Modify: `src/sizeResolver.js`
- Modify: `src/background.js`
- Modify: `src/popup.js` (oznaczanie odrzuconych)
- Modify: `tests/sizeResolver.test.mjs`

- [ ] **Step 1: Waliduj content-type w `resolveImageSize`**
  Zwróć `{ sizeBytes, contentType }` (zamiast samego int) albo `null` gdy `content-type` istnieje i nie zaczyna się od `image/`. Brak nagłówka = akceptuj (serwery bez HEAD). Zaktualizuj sygnaturę + cache w `background.js`.
  ```js
  // szkic
  const ctype = headResponse?.headers?.get("content-type") || rangeResponse?.headers?.get("content-type");
  if (ctype && !ctype.startsWith("image/")) return null; // + oznacz kandydata jako rejected
  ```
- [ ] **Step 2: Oznaczaj odrzucone w popupie**
  Kandydaci odrzuceni przez content-type wypadają z `currentImages` (nie „unknown size"). Status pokazuje np. `X ignored (not images)`.
- [ ] **Step 3: Testy**
  Dodaj testy: `content-type: text/html` → null; `image/webp` → rozmiar; brak nagłówka → rozmiar. Run: `npm test` → PASS.
- [ ] **Step 4: Weryfikacja manualna**
  Strona z API/analityką bez rozszerzeń (np. jakikolwiek blog). Expected: śmieciowe URL-e znikają z listy.
- [ ] **Step 5: Commit**
  `git commit -m "fix: reject non-image content-type in size probe"`

- [ ] **Step 1: Batchuj aktualizacje rozmiarów**

- [ ] **Step 5: Unieważnianie batcha przy refresh**
  `renderBatcher` dostaje `cancel()` wołane na starcie `refresh()` (koniec R17).
